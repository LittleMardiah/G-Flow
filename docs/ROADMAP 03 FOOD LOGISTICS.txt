3.3.3 POST /food-orders (Create Food Order) — FIXED: Dual-Layer Idempotency
  Auth: Required (customer)
  Idempotency: REQUIRED (X-Idempotency-Key)
  Rate Limit: 20 req/min per user

  **IDEMPOTENCY MANDATE (FIXED):**
  - L1 Redis cache: Fast lookup with 24h TTL
  - L2 PostgreSQL idempotency_cache table with unique constraint (key, user_id)
  - If Redis down, L2 still prevents duplicates
  - If same key within 24h: return cached response (200 OK)
  - If same key with different payload: return 409 CONFLICT

  Request:
  {
    "merchant_id": "uuid",
    "delivery_address": "Jl. Sudirman 456, Jakarta",
    "delivery_lat": -6.2950,
    "delivery_lng": 106.8638,
    "payment_method": "WALLET",  // or "CASH"
    "items": [
      {
        "item_id": "uuid",
        "quantity": 2,
        "options": {
          "size": "Large",
          "topping": "Extra cheese"
        },
        "special_instructions": "No onion"
      }
    ],
    "voucher_id": "uuid?"  // optional
  }

  Business Logic:

  1. VALIDATE
     - Customer wallet status = ACTIVE
     - Merchant status = ACTIVE (verify merchant exists)
     - Delivery address valid (non-null, coordinates OK)
     - All items exist & is_available = TRUE
     - Stock >= quantity for each item (optional in MVP)
     - ✅ OVERDUE DEBT CHECK (UNIVERSAL): Reject if customer has overdue_debt > 0
       (for both WALLET & CASH payment methods)

  2. IDEMPOTENCY CHECK (L1 + L2)
     - Check Redis: GET "idempotency:{key}"
     - If hit: return cached response (200 OK)
     - If miss: INSERT into idempotency_cache (key, user_id, status='PROCESSING', expires_at)
     - If duplicate INSERT violation: query cached response and return
     - On success: store response in Redis + update PG status='COMPLETED'

  3. CALCULATE PRICES
     - item_subtotal = SUM(item_price * quantity + options_total)
     - delivery_fee = Rp 20,000 (fixed in MVP)
     - Apply voucher discount if provided (PERCENTAGE or FIXED)
     - platform_commission = item_subtotal * 0.15 (15%)
     - driver_earning = delivery_fee * 0.90
     - total_amount = item_subtotal + delivery_fee - discount_amount

  4. DEDUCT ESCROW (conditional on payment_method)
     - IF payment_method = 'WALLET':
       - BEGIN TRANSACTION
       - Lock customer wallet: SELECT ... FOR UPDATE
       - Check balance >= total_amount
       - Create 2 ledger entries (atomically):
         * DEBIT customer_wallet: total_amount
         * CREDIT system_escrow_wallet: total_amount
       - COMMIT
       - Set status = 'CONFIRMED' (payment already secured)
     - IF payment_method = 'CASH':
       - ⚠️ JANGAN potong wallet saat booking
       - Validasi customer tidak punya overdue debt
       - Set status = 'CREATED' (waiting merchant confirmation)

  5. CREATE ORDER
     - INSERT food_orders:
       * status: 'CONFIRMED' (WALLET) OR 'CREATED' (CASH)
       * merchant_status: 'WAITING' (pending merchant action)
       * is_settled: FALSE

  6. CREATE ORDER ITEMS
     - INSERT food_order_items (loop through items array)
     - Store item_name, item_price, quantity, subtotal, options (JSONB)

  7. APPLY VOUCHER
     - IF voucher_id provided:
       - UPDATE vouchers SET remaining_count = remaining_count - 1, last_used_at = NOW()
       - ADD UNIQUE CONSTRAINT on (order_id, voucher_id)
     - Voucher rollback on order cancellation (trigger: rollback_voucher_soft_delete)

  Response:
  {
    "id": "uuid",
    "status": "CONFIRMED",
    "total_amount": 85000,
    "estimated_delivery_time": "30 minutes"
  }

3.4 FOOD ORDER STATUS MACHINE & SETTLEMENT (F009) — FIXED: ORDER BY id ASC
────────────────────────────────────────────────────────────────────────────────

Order Status Flow:
  CREATED
    ↓ (Merchant confirms — WALLET payment only, CASH stays CREATED until driver pickup)
  CONFIRMED
    ↓ (Merchant starts preparation)
  PREPARING
    ↓ (Food ready for pickup)
  READY_FOR_PICKUP
    ↓ (Driver picks up order)
  PICKED_UP
    ↓ (Driver in transit to customer)
  IN_TRANSIT
    ↓ (Driver arrives & delivers)
  DELIVERED
    ↓ (Automatic settlement trigger)
  SETTLED
    ✅ (Payment distributed)

Edge Cases:
  - Customer can cancel CREATED or CONFIRMED → CANCELLED + Refund (if WALLET)
  - Merchant can reject CREATED → CANCELLED + Refund (if WALLET)
  - Driver can cancel during READY_FOR_PICKUP or PICKED_UP (emergency) → refund logic
  - If CASH: settlement doesn't deduct customer, only credits merchant + driver

4-Way Settlement Logic (On DELIVERED → SETTLED transition) — FIXED: ORDER BY id ASC:
  
  Total amount = customer paid
  
  Breakdown:
  1. Merchant receives: item_subtotal - platform_commission
  2. Driver receives: driver_earning (already calc'd as delivery_fee * 0.9)
  3. Platform receives: platform_commission
  4. Customer: already paid (WALLET) or owes cash (CASH)

  Math verification:
  merchant_earning + driver_earning + platform_commission = item_subtotal + delivery_fee - discount
  (Should always balance)

  **LOCK HIERARCHY MANDATE (FIXED):**
  - BEGIN TRANSACTION
  - SET LOCAL statement_timeout = '5000ms'
  - walletIDs := []uuid.UUID{merchant_wallet_id, driver_wallet_id, escrow_wallet_id, platform_wallet_id}
  - sort.Slice(walletIDs, func(i, j int) bool { return walletIDs[i].String() < walletIDs[j].String() })
  - SELECT * FROM wallets WHERE id IN (walletIDs) ORDER BY id ASC FOR UPDATE
  - Create 4 ledger entries atomically:
    * CREDIT merchant_wallet: (item_subtotal - platform_commission)
    * CREDIT driver_wallet: driver_earning
    * CREDIT platform_wallet: platform_commission
    * DEBIT escrow_wallet: total_amount
  - UPDATE food_orders SET status = 'SETTLED', is_settled = TRUE, settled_at = NOW()
  - COMMIT

  Cash Settlement:
  - If payment_method = 'CASH':
    - Driver collects cash from customer
    - settlement_type = 'CASH'
    - Process cash settlement via trigger: process_cash_settlement()
      * Check driver balance after distribution
      * If driver_balance < -50.000, mark driver as 'SUSPENDED'

  [ ] Cash settlement handling (balance check, suspension)
  [ ] Settlement audit trail (INSERT food_order_events)

3.5.1 POST /send-orders (Create Send Order) — FIXED: Dual-Layer Idempotency
  Auth: Required (customer)
  Idempotency: REQUIRED (X-Idempotency-Key)
  Rate Limit: 20 req/min per user

  **IDEMPOTENCY MANDATE (FIXED):**
  - L1 Redis cache: Fast lookup with 24h TTL
  - L2 PostgreSQL idempotency_cache table with unique constraint (key, user_id)
  - If Redis down, L2 still prevents duplicates
  - If same key within 24h: return cached response (200 OK)
  - If same key with different payload: return 409 CONFLICT

  Request:
  {
    "pickup_lat": -6.2088,
    "pickup_lng": 106.8456,
    "pickup_address": "Office, Jl. Gatot Subroto",
    "package_weight_kg": 2.5,
    "package_dimensions_cm": "30x20x15",
    "package_description": "Documents & gifts",
    "package_type": "STANDARD",  // or FRAGILE, LIQUID, ELECTRONICS
    "declared_value": 500000,
    "payment_method": "WALLET",  // or "CASH"
    "stops": [  // Multi-stop: 1-3 deliveries
      {
        "recipient_name": "Budi",
        "recipient_phone": "0821-xxx",
        "delivery_address": "Jl. Sudirman 456",
        "delivery_lat": -6.2950,
        "delivery_lng": 106.8638
      },
      {
        "recipient_name": "Siti",
        "recipient_phone": "0821-yyy",
        "delivery_address": "Jl. Thamrin 789",
        "delivery_lat": -6.1950,
        "delivery_lng": 106.8138
      }
    ]
  }

  Business Logic:

  1. VALIDATE
     - Customer wallet status = ACTIVE
     - Pickup address valid
     - All delivery addresses valid
     - stops.length between 1-3 (multi-stop limit)
     - package_weight_kg > 0
     - declared_value >= 0
     - ✅ OVERDUE DEBT CHECK (UNIVERSAL): Reject if overdue_debt > 0

  2. IDEMPOTENCY CHECK (L1 + L2)
     - Check Redis: GET "idempotency:{key}"
     - If hit: return cached response (200 OK)
     - If miss: INSERT into idempotency_cache (key, user_id, status='PROCESSING', expires_at)
     - If duplicate INSERT violation: query cached response and return
     - On success: store response in Redis + update PG status='COMPLETED'

  3. CALCULATE FARE
     - Base fare: Rp 15,000
     - Weight surcharge: if weight_kg > 5, add Rp 2,000 per kg
     - Distance calculation:
       * For single stop: distance from pickup to delivery
       * For multi-stop: sum of distances (pickup→stop1→stop2→...)
       * Haversine formula via earthdistance
     - per_km_rate: Rp 3,000 per km
     - total_fare_before_stops = base_fare + (distance_km * per_km_rate) + weight_surcharge
     - insurance_fee: if declared_value > 100.000, add 1% of declared_value (max Rp 50,000)
     - Applied discount: if voucher_id provided
     - total_fare = total_fare_before_stops + insurance_fee - discount

  4. ALLOCATE FARE TO STOPS (Multi-Stop)
     - If single stop: allocated_fare = total_fare
     - If multi-stop: allocate proportionally by distance
       * For each stop: allocated_fare = total_fare * (stop_distance / total_distance)
       * Round to nearest 1000 (or use exact decimal if consistent)

  5. DEDUCT ESCROW (conditional on payment_method)
     - IF payment_method = 'WALLET':
       - BEGIN TRANSACTION
       - Lock customer wallet: SELECT ... FOR UPDATE
       - Check balance >= total_fare
       - Create 2 ledger entries:
         * DEBIT sender_wallet: total_fare
         * CREDIT system_escrow_wallet: total_fare
       - COMMIT
       - Set status = 'SEARCHING_DRIVER'
     - IF payment_method = 'CASH':
       - ⚠️ JANGAN potong wallet
       - Set status = 'SEARCHING_DRIVER'
