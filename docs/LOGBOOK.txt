TASK 2.3 - Dispatch Matching Engine (F005) — CRITICAL RACE CONDITION
================================================================================
Status: ✅ SELESAI

Apa yang dilakukan:
1. Tambahkan repository method:
   - `GetDriver`, `GetDriverBalance`, `LockOrderForAccept` (SELECT FOR UPDATE NOWAIT), `AssignDriver`, `MarkDriverBusy`.
2. Tambahkan service method `AcceptOrder`:
   - Lock driver user (FOR UPDATE NOWAIT) → baca working_status & min_balance.
   - Baca balance driver (tanpa lock) → cek min_balance.
   - Lock order (FOR UPDATE NOWAIT) dengan status SEARCHING_DRIVER.
   - Update order status → DRIVER_ASSIGNED, set driver_id, assigned_at.
   - Update driver working_status → BUSY.
   - Insert audit event (SEARCHING_DRIVER → DRIVER_ASSIGNED).
   - Error handling: 409 (order not available, driver busy), 422 (driver invalid, insufficient balance), 503 (lock timeout).
3. Handler `AcceptOrder` di `handler.go` + route `POST /api/v1/rides/:order_id/accept`.
4. Integration test `TestIntegrationRide_ConcurrentAccept` (10 goroutine accept 1 order → 1 success, 9 conflict).

Hasil Verifikasi:
- ✅ Pessimistic locking dengan `FOR UPDATE NOWAIT` berhasil.
- ✅ 10 driver concurrent → 1 sukses (200), 9 conflict (409).
- ✅ Zero double-booking di database.
- ✅ Driver busy guard (working_status = 'IDLE') mencegah driver menerima order lain.
