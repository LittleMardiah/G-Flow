A. KRITIS (CRITICAL) - Data loss, security breach, atau system crash
--------------------------------------------------------------------------------

ID : TD-001
Kategori : SECURITY
Judul : Wallet handler masih memakai ResolveUserIDByWallet, JWT claim belum
        terintegrasi penuh
Dampak : Pemilik wallet tidak diverifikasi dari JWT claim; risiko akses/perintah
         lintas pemilik (privilege/authorization breach) pada top-up & transfer.
Solusi : Ambil user_id dari c.GetString("user_id") (claim JWT) di wallet handler
         dan hapus ResolveUserIDByWallet. Terapkan RLS/ownership check.
Estimasi : 1-2 jam
Prioritas : KRITIS
Status : FIXED (commit b6f2f49, 2026-08-31)

ID : TD-002
Kategori : DATABASE / RELIABILITAS
Judul : Tidak ada index untuk idempotency_cache (key, user_id) & periode
        pembersihan (purge) record kedaluwarsa
Dampak : Query idempotency (L2) dan akumulasi cache bisa melambat / membesar
         tanpa batas, meningkatkan risiko time lag pada path kritis pembayaran.
Solusi : Buat index komposit (key, user_id); tambahkan job purge idempotency_cache
         expired (24h) secara berkala.
Estimasi : 45 menit - 1.5 jam
Prioritas : KRITIS
Status : FIXED (commit b6f2f49, 2026-08-31)

C. SEDANG (MEDIUM) - Mengurangi maintainability atau performance
--------------------------------------------------------------------------------

ID : TD-011
Kategori : ARSITEKTUR
Judul : Overdue debt belum terintegrasi penuh antar-modul (baru di jalur top-up /
        gate booking; belum seluruh jalur settlement)
Dampak : Debt mungkin tidak tercatat konsisten di semua alur (mis. delta fare
         settlement food/send) → potensi saldo negatif tanpa audit debt.
Solusi : Standarkan mekanisme pencatatan overdue_debt di semua settlement
         (ride/food/send) + deduksi saat top-up berikutnya.
Estimasi : 2-4 jam
Prioritas : SEDANG
Status : OPEN

ID : TD-012
Kategori : DATABASE
Judul : Belum ada index untuk topup_transactions (status, created_at) dan
        beberapa query filter status/created_at pada ride/food/send
Dampak : Query webhook & auto-cancel worker yang memfilter status+timestamp bisa
         lambat saat volume transaksi membesar.
Solusi : Tambahkan index komposit (status, created_at) pada
         topup_transactions, ride_orders, food_orders, send_orders.
Estimasi : 1-2 jam
Prioritas : SEDANG
Status : OPEN

ID : TD-013
Kategori : KODE
Judul : Logger masih default slog INFO, belum konfig log level per environment
Dampak : Log terlalu verbose di prod atau kurang detail di dev; sulit diagnosa.
Solusi : Konfigurasi level (DEBUG/WARN/INFO) dari env (APP_ENV).
Estimasi : 30-45 menit
Prioritas : SEDANG
Status : OPEN

ID : TD-014
Kategori : KODE / INFRA
Judul : Redis client tanpa graceful shutdown & tanpa cleanup key TTL konsisten
        pada beberapa path (worker/location)
Dampak : Koneksi Redis bisa bocor saat shutdown; sisa key dapat mengaburkan
         status driver/order.
Solusi : defer rdb.Close() di main.go; pastikan TTL & penghapusan key konsisten
         (mis. driver:location, distributed lock) pada semua worker.
Estimasi : 45 menit
Prioritas : SEDANG
Status : OPEN

ID : TD-015
Kategori : ARSITEKTUR
Judul : Definisi status stop send order tidak konsisten antara ROADMAP (DELIVERED)
        dengan implementasi (discrepancy tercatat di LOGBOOK 3.6)
Dampak : Mapping status stop vs order bisa ambigu & menyulitkan settlement/kontrol.
Solusi : Seragamkan enum status stop (send_order_stops) dengan ROADMAP & validasi
         transisi.
Estimasi : 1-2 jam
Prioritas : SEDANG
Status : OPEN
